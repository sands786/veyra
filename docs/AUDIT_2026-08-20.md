# Veyra Full-Stack Audit — 20 August 2026

## Scope and method

This evidence-led audit covers build reproducibility, dependency posture, server authorization and persistence boundaries, lifecycle enforcement, public privacy surfaces, and representative responsive UI routes. Findings are only recorded when confirmed from the authored source, a test/build result, or a rendered application surface.

## Confirmed findings in remediation

| ID     | Finding                                                                                                                                                                                                  | Boundary                       | Status              |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ | ------------------- |
| AUD-01 | A public claim response returned the route-wide total rather than the recipient allocation represented by the bearer token. | Privacy / selective disclosure | Fixed: public claims now join and release only the assigned recipient allocation. |
| AUD-02 | Claim redemption read a pending claim and updated it without proving that the conditional update won the race. | Integrity / replay safety | Fixed: expiry-aware conditional write and dependent updates run in one database transaction; a non-winning request fails closed. |
| AUD-03 | Route creation and editing accepted duplicate recipient IDs and did not verify that allocation amounts added exactly to the stated route total. | Financial data integrity | Fixed: strict decimal allocation validation plus a database unique constraint on `(routeId, recipientId)`. |
| AUD-04 | Backend route status changes verified approvals before settlement but did not enforce a complete server-side route transition graph. | Lifecycle integrity | Fixed: shared route-state graph now gates every backend transition. |
| AUD-05 | The direct dependency graph contained outdated production packages, and an Express 5 upgrade exposed legacy wildcard-route syntax. | Supply chain / deployment reliability | Fixed: upgraded Axios, tRPC, Drizzle, NanoID, and Express; removed unused Streamdown/Recharts template modules; converted all Express wildcards to named Express 5 routes. |

## Current deployment boundary

The Vercel client bundle and its managed API rewrite have been validated. Manus OAuth still blocks the external Vercel callback origin at the platform allowlist; this is tracked separately and does not change the audit findings above.

## Final validation

The hardened release served the local root route with HTTP 200, passed all 78 regression tests, completed both `pnpm build:vercel` and `pnpm build`, and returned no production dependency advisories in the final audit scan. The remaining Vercel OAuth rejection is an external Manus callback-origin allowlist decision rather than an application defect.

## Independent second pass

A separate follow-up pass re-ran the entire 78-test suite, confirmed no legacy Express wildcard syntax remained, re-checked the live database metadata for the non-unique `(routeId, recipientId)` pair constraint, exercised invalid public claim and proof routes, and rebuilt both deployment targets. The root route again returned HTTP 200 and the repeated production dependency audit remained clean. No new application defect was confirmed.
